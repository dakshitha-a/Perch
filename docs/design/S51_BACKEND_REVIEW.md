## Must-fix

- **E1 A guest gets about one explained brief per session:** The deploy never sets `PERCH_GUEST_DAILY_BUDGET_USD`, so each guest session has the placeholder default of $0.10 a day. The Demo Day decision raised only the address budget ($4.00) and the global guest budget ($8.00). The deploy ledger shows bursts of 8 to 12 calls costing $0.05 to $0.09, which is about one brief. So a guest's second brief loses its later explanations once the reservations hit the cap. After that, `admit_guest` refuses every explained brief from that guest with a 429 `quota_exceeded`. A guest who builds a researcher brief and then the sample student brief will hit this on stage. The fix is to set the session budget in the deploy settings, for example $0.50, and add the variable to `.env.example`, which does not list it. Note also that the address budget counts per UTC day, which starts at 7 pm in Philadelphia, so a rehearsal from the venue network the evening before uses up the same $4.00. Where: perch/redisx.py:218, perch/user/quota.py:82, perch/user/briefs.py:738, perch/api.py:727. Effort: S.

- **E2 The presenter's Scout, hand-off and cover-point jobs wait behind the audience's briefs:** The worker runs 8 job threads, and every thread claims every kind. Priority only decides which queued job a free thread takes next, so it does not help while all 8 threads are busy. With 30 guests building briefs, all 8 threads run briefs for minutes at a time, and they queue on the one model slot. A `scout_turn` from the presenter, priority 0, then waits until a brief finishes. A wait of a minute or more in the middle of the live demo is likely. The fix is to reserve one or two threads that never claim `brief` or `precache`, in the same way the precache semaphore works. Where: perch/jobs.py:623-651. Effort: S.

- **E3 The public sign-in realm may still accept the repository's e2e password, and it has no brute-force lockout:** The S50 change rotates `synthetic-user-1`'s password only when the e2e script runs. The user is created with the tracked placeholder password and is reset right after. If the script has not run since the change, or it failed between the create and the reset, the tracked password still signs anyone into the public deploy. That account can spend its $5.00 day budget. Separately, `perch-realm.json` does not set `bruteForceProtected`, so Keycloak's lockout is off for the demo accounts. The fix is to check the user on the live realm and disable it between runs, and to create it with a random password instead of the tracked one. Also turn on brute-force detection for the realm. Where: scripts/e2e_oidc_login.py:226-245, deploy/compose/keycloak/e2e-user.json, deploy/compose/keycloak/perch-realm.json:4. Effort: S.

## Should-fix

- **E4 The guest brief limit was raised for an address, but it counts per session:** The decision raised `guest_job` to 60 per 10 minutes, on the reading that it was per address. The code keys it by guest session (`rate_limit(r, "guest_job", gh)`), so each of the 30 guests already had their own 5. A brief with `explain: false` skips `admit_guest` entirely and costs no money but uses the GPU. So one visitor can now queue 60 such briefs every 10 minutes per session, with 600 new sessions an hour allowed per address. That fills all 8 threads, which makes E2 worse. The fix is to put `guest_job` back to its default, or to key it by address. Where: perch/user/briefs.py:734-738, perch/request_models.py:27. Effort: S.

- **E5 Scout's `get_record` says the deadline is "None (the record's own words)":** G8 made `placeholder_close` true for any date more than ten years out, with or without a note. Twelve records carry 1 Jan 2099 with no note. `get_record` still builds the deadline from `rec.close_date_note`, which is None for those records. This was confirmed on a test record. The other renderers moved to `placeholder_text`, but this one did not. It is reached through the MCP server and the student tool table. Where: perch/scout/tools.py:518-523. Effort: S.

- **E6 The deploy's public host name is in tracked files:** `docs/HANDOFF.md` (two lines) and `scripts/live_capture.py` (the `BASE` constant) hold the test deploy's public URL. The public-ready rule bars machine names, and these files go into the submission ZIP and the public repo. `test_public_hygiene.py` has no pattern for the tunnel domain, so it passes. The fix is to read the URL from the environment, move the note to the local file, and add the domain pattern to the hygiene test. Git history keeps the old lines. Where: docs/HANDOFF.md:31, docs/HANDOFF.md:35, scripts/live_capture.py:17, tests/test_public_hygiene.py. Effort: S.

- **E7 Merging copies of an award can keep the copy limited to one school:** `_keep` takes the fellowships office's copy, or else the copy with the most fields set. A school page's copy sets `schools` and `scope`, so it can beat the university-wide copy. In `temple_awards_v3` this happens to CARAS (a Fox copy and an Undergraduate Studies copy), Supplemental Academic Scholarships (Student Financial Services and Fox), and Temple Promise (Student Financial Services and Liberal Arts). The card then says "School: open to students of Fox School of Business" for an award open across the university. That claim is wrong, and the record does not back it. The fix is to prefer the copy with no school limit when the copies disagree on schools. Where: perch/student.py:624-629, perch/student.py:428. Effort: S.

- **E8 A worker restart on Demo Day queues the day's failed precache jobs again:** The scheduler remembers in memory that it has enqueued the precache, so it forgets after a restart. Precache keys are unique only among live jobs (a partial index on queued, running and succeeded). So a restart after 08:00 UTC inserts a new job for every author whose precache failed or died that day. Those jobs then run one at a time and hold the model slot during the demo. The fix is to skip an author whose key already has a row in any state, as the purge keys already do. Where: perch/jobs.py:778-789, perch/precache.py:42-56, perch/db/migrations/perch/0002_tables.sql:115. Effort: S.

- **E9 A model server's retry sleeps while it holds the only model slot:** `retry.post` sleeps 1 s and then 3 s between attempts. With a `Retry-After` header, each sleep can be up to 10 s. The remote embedder, reranker and grounder call it inside `model_slot()`, so a busy model server stops every other job's GPU call for up to 20 s. The fix is to retry outside the slot, or to give the slot back before sleeping. Where: perch/llm/retry.py:35-43, perch/remote_models.py:31, perch/remote_models.py:48, perch/remote_models.py:61, perch/compute.py:128-152. Effort: S.

- **E10 A shortened link still passes the validator, and its digits go unchecked:** This is C17, still open. A link passes when it appears anywhere inside a cited record's text or URL. So the first part of a Grants.gov detail URL passes. Its digits are then removed before the number check, so a wrong id inside a link goes through as well. This breaks standing rule 3. The fix is to accept a link only when it is a whole URL in the evidence or equal to `source_url`. Where: perch/validate.py:138-149. Effort: S.

- **E11 A malformed `PERCH_RATE_LIMITS` breaks every rate-limited route:** `rate_table()` parses the JSON on every call. A typo in the setting raises `JSONDecodeError`. The browse and resolve routes catch only `RedisError`, so they return 500, and the auth and job routes fail the same way. This setting was edited for Demo Day. The fix is to parse the setting once at start-up and stop the process with a clear error when it is bad. Where: perch/redisx.py:292-298, perch/browse/routes.py:79, perch/api.py:656. Effort: S.

- **E12 The brief error text now on My Perch can hold server text:** On the worker, `quiet_errors` stays False. So a signed-in researcher brief with no documents stores its error as the exception type plus the full message. A local model's `ProviderError` message includes up to 300 characters of the server's response, and an httpx error includes the request URL. S50 shows this text on My Perch as well as on the brief page. The fix is to use `plain_error` for every v1 brief, by setting `quiet_errors=True` in `cmd_worker`. Where: perch/service.py:145, perch/service.py:325, perch/user/routes.py:196, perch/llm/openai_compat.py:83. Effort: S.

- **E13 One failing user stops the inactivity purge for everyone after them:** `purge_inactive` catches only `CryptoError` from `delete_account`. Any other error stops the whole batch, such as a database error in `_cancel_jobs` or in `clear_rows`. The retry starts again from the same user, because they are first by `last_active_at`. After five attempts the job dies, and the next day goes the same way. So the 12-month deletion of standing rule 1 stops for every user after that one. The fix is to catch per user, queue `queue_purge_retry` for that user, and go on. Where: perch/user/delete.py:93-103. Effort: S.

Return 202 with a note instead. Where: perch/user/routes.py:175-179, perch/user/delete.py:56-77. Effort: S.
